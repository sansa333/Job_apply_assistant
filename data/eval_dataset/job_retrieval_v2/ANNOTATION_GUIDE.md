# Job Retrieval V2 人工标注规范

## 标注对象

标注单位是一个具体自然查询和一个具体 JD 证据片段。标注者只能根据片段文本判断它对查询的支持
程度，不得因为公司知名度、岗位标题相似或个人行业常识而补充片段中不存在的信息。

## 四级标签

- `3 直接回答`：片段直接给出查询所需的职责、技能、资格或工作条件，单独引用即可支持回答。
- `2 相关`：片段提供回答所需的重要组成部分，但必须与其他片段组合才能完整回答。
- `1 弱相关`：主题相近或提供背景，但不能作为该问题结论的直接证据。
- `0 不相关`：没有回答查询，或只是出现相同技能名但描述的是另一家公司、另一岗位或不同工作语境。

检索指标中的相关集合定义为等级 2 和 3。等级 0–3 全部保留，用于计算 nDCG@K。

## 困难负例判断

标注界面会混入以下候选，不能仅凭关键词判为相关：

- 同一 JD 中相邻但回答另一类问题的段落。
- 同岗位族、另一家公司中描述相同技能的段落。
- 同一个技术名词但职责层级不同，例如“使用模型”与“负责模型平台架构”。
- 相同工作模式词汇但地点、合同或适用条件不同。
- 公司文化、平等机会声明等通用内容。

## 双标与仲裁流程

1. 标注者 A 只填写 `annotator_1_grade`。
2. 标注者 B 在不可见 A 结果的情况下只填写 `annotator_2_grade`。
3. 一致项自动采用共同等级。
4. 不一致项由第三名仲裁者阅读查询、片段和两方理由后填写 `adjudicated_grade`。
5. 标注完成后运行 `python -m tools.finalize_retrieval_v2_annotations`。
6. Kappa 低于 0.70 时不得发布 gold qrels，应复训标注者并重新标注低一致性类别。

## 质量抽检

- 正式标注前，三人共同完成 50 个校准样本并讨论分歧。
- 每完成 1,000 个判断，随机抽检 50 个。
- 分别统计四种 query type 和八个岗位族的一致性，不能只看总体 Kappa。
- 若某类等级 3 比例异常高，检查是否把关键词出现误判为直接回答。
- 若某条查询所有候选均小于 2，标记为 `query_has_no_relevant_passage` 并回到查询设计阶段处理。

## 禁止事项

- 不得批量复制 silver 标签到人工字段。
- 不得由同一人填写两个标注者字段。
- 不得为达到 Kappa 阈值而删除分歧样本。
- 不得在看过冻结 Test 结果后修改 Test qrels，再继续使用同一版本号。
