# 意图识别失败处理与执行门禁

实施日期：2026-09-12。

## 本次实现

请求先经过意图识别，再经过程序执行门禁；不确定的分类不会再自动进入动态 Agent。

1. 调用方声明、高精度关键词、严格限定的连续修改规则优先；其他表达由模型分类并抽取本轮明确出现的公司/岗位。
2. 分类缺失、低于 0.75 或存在未消解的多任务歧义，返回 `needs_clarification / awaiting_intent_confirmation`，附问题、选项和 `confirm_intent`。创建 ApplicationService、调用领域工具和创建 Agent 都在这个门禁之后。
3. 任务已确定时，复用 `plan_workflow` 检查公司、岗位和候选证据入口。缺身份返回 `needs_job_identity`，缺证据返回 `needs_candidate_evidence`，不会反复询问任务类型。真实岗位存在性、候选人片段是否为空、生成事实校验仍在原领域服务内完成；这里没有用分类器结果替代数据库验证。
4. 新增 `agent_routing_state` 表，按已有会话/候选人权限保存待澄清意图、候选选项及缺失字段；不保存本轮完整简历或 JD。数据库初始化会创建新表，旧表不重建。删除会话时外键级联清除。
5. 会话可用“第一个”“第二个”或问题中展示的任务名称继续。已知任务的缺字段流程可在填好字段后回复“已补充”或“继续”。取消会清除待澄清状态和上一意图。匿名无会话请求保持无状态，客户端须在下一次请求明确传 `intent` 和所需字段，不能期待序号跨请求生效。
6. 收窄连续修改规则，不再因一句话含单字“再”就沿用旧意图。当前文本抽取可覆盖历史身份；模型新抽取的字段必须出现在本轮文本中。表单与本轮文本冲突时要求确认。新目标无法在模型故障时确定，不能回退到旧岗位执行。已绑定 `job_id` 的会话保留原项目的禁止重绑定规则，切换目标返回 `needs_new_conversation`。
7. 六个工具定义保留，但每次请求按意图过滤可见工具；申请包工具仅对申请包意图放行。工具执行包装还会校验工具范围、候选人与目标岗位，并用请求中的证据/联系方式覆盖模型拟造的参数。固定流程与动态 Agent 共用包装。
8. Agent 已开始执行后发生异常，不再切换旧版 API 重跑整个请求；返回 `agent_execution_error`，明确部分工具可能已执行，要求先核对已有结果。这不等于已经实现通用事务回滚或所有写操作的幂等。

## 分类器失败恢复

分类器最多两次模型调用，传输恢复与格式修复共享这个次数预算。

| 情况 | 行为 |
|---|---|
| 连接错误、超时、408/429、5xx | 有限抖动等待后最多重试一次 |
| JSON 解析或字段校验错误 | 最多补一次格式修复请求 |
| 参数、权限等非暂时性提供商错误 | 不重试，尝试规则兜底 |
| 模型正常输出但意图不明确/置信度低 | 不重试，交执行门禁澄清 |
| 编造本轮未出现的新公司/岗位 | 标记 `ungrounded_identity`，澄清 |
| 规则也无法判断 | 澄清，不进入动态 Agent |

分类器复制模型配置，禁用 SDK 内部重试，以免与外层叠加。默认每次请求超时 8 秒、最多输出 400 tokens；生成模型原配置不变。这里限制的是单次网络超时和调用次数，不承诺严格的整个 HTTP 请求端到端 deadline。环境变量：

```text
AGENT_INTENT_TIMEOUT_SECONDS=8
AGENT_INTENT_RETRY_DELAY_SECONDS=0.2
AGENT_INTENT_JSON_MODE=false
```

支持 `response_format=json_object` 的提供商可开启 JSON 模式；这只帮助保证 JSON 格式，枚举/类型和业务约束仍由程序校验，不等于提供商侧严格 JSON Schema。

响应新增 `clarification_question`、`intent_options`、`field_sources`、`routing_diagnostics`。诊断记录分类器尝试次数、错误类别和识别耗时，不附模型原始错误正文或完整候选人资料。Streamlit 与 HTML 界面原有结果区域可显示澄清问题，在同一会话输入回复即可。

### 可口述的失败处理回答

我按失败原因处理。意图识别超时或遇到暂时性服务错误，最多重试一次；输出格式不合法时，有限修复后再校验。仍失败就回退规则，规则也不能确定任务时，程序会停在待澄清状态，问用户想做什么，不会继续让 Agent 猜着调用工具。确认后才检查目标岗位和候选人资料；岗位不存在或没有证据，返回明确的补资料动作，而不是盲目重试。澄清状态会保存在会话里，下一轮能接着完成。动态 Agent 执行中途失败，也不会自动重放整项任务，因为前面的工具可能已经执行过。

如果被追问“效果怎样”，可以说明相关失败、接续和越权场景已经通过本地回归，离线策略样例逐项可复现；尚未测量真实用户下的意图准确率和澄清完成率。
