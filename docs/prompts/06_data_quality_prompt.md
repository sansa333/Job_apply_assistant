# 06 Data Quality Prompt

## 任务目标

治理当前项目中的中文乱码、样例数据不一致、文件编码不统一、入库文本质量不可控等问题，为 RAG 效果提供更稳定的数据基础。

## 当前项目背景

项目中部分示例文件和输出文件出现中文乱码，但 `data/applications.csv` 中存在正常中文记录。这说明某些文件可能在创建、读取、写入或终端显示过程中编码不一致。

RAG 对数据质量敏感。如果入库文本乱码、重复、格式混乱，会直接影响检索和生成质量。

## 需要检查的代码位置

- `data/profile_docs`
- `data/jd_docs`
- `data/mm_docs`
- `outputs`
- `app/rag.py`
- `app/utils/file_io.py`
- `app/services/document_service.py`
- `app/multimodal/service.py`

## 推荐实施流程

1. 扫描项目中的文本文件：
   - `.md`
   - `.txt`
   - `.csv`
   - `.json`
2. 检测编码和乱码特征：
   - UTF-8
   - UTF-8 with BOM
   - GBK/GB18030
   - mojibake 常见模式
3. 统一读取策略：
   - 优先 UTF-8
   - 失败时尝试 UTF-8-SIG、GB18030
   - 记录实际编码
4. 统一写入策略：
   - Markdown / JSON 使用 UTF-8
   - CSV 如需 Excel 兼容可使用 UTF-8-SIG
5. 增加数据清洗：
   - 去除空白噪声
   - 修复异常换行
   - 过滤过短 chunk
   - 保留原始文件备份
6. 重建干净样例数据：
   - example resume
   - example JD
   - multimodal example text
7. 建立数据质量报告：
   - 文件路径
   - 检测编码
   - 是否疑似乱码
   - 修复动作

## 验收标准

- 示例简历和 JD 能正常显示中文。
- 新生成的 JSON、Markdown、CSV 无乱码。
- 文本入库时能兼容常见中文编码。
- 数据质量扫描能发现疑似乱码文件。
- 清洗流程不会覆盖原始文件，或覆盖前有备份。

## 风险点

- 已经乱码的文本不一定能 100% 自动恢复。
- CSV 为了 Excel 兼容可能需要 UTF-8-SIG，但代码读取要兼容。
- 不要盲目批量覆盖用户真实数据。
- 入库前清洗不能删除业务关键信息。

## 完整提示词

```text
你是一名数据质量与中文编码治理工程师。请为当前 RAG 项目治理文本编码和数据质量问题。

项目背景：
- 当前项目包含 data/profile_docs、data/jd_docs、data/mm_docs、outputs 等目录。
- 部分 markdown/json 输出存在中文乱码。
- RAG 入库依赖 TextLoader 和本地文件读取，数据质量会直接影响检索效果。

请完成以下任务：
1. 扫描项目中的 md、txt、csv、json 文件，检测编码和疑似乱码。
2. 设计统一读取函数，优先 UTF-8，失败时尝试 UTF-8-SIG、GB18030。
3. 设计统一写入规范：Markdown/JSON 使用 UTF-8，CSV 根据 Excel 兼容需求使用 UTF-8-SIG。
4. 修复或重建示例简历、示例 JD、多模态示例文本，确保中文正常。
5. 增加入库前文本清洗流程，包括去除异常空白、过滤过短内容、保留必要换行。
6. 生成数据质量报告，列出文件路径、编码、是否疑似乱码、处理动作。
7. 确保修复过程不盲目覆盖用户真实数据；必要时保留备份。
8. 补充最小验证：读取示例文件、入库、检索，确认中文关键词可命中。

实现要求：
- 不要删除用户已有数据。
- 不要把所有文件强行按一种编码解码。
- 对无法可靠修复的乱码文件，标记为需要人工确认。
- 数据清洗逻辑应可复用，不要散落在多个业务函数中。

最后请输出：
1. 数据质量扫描结果。
2. 编码治理策略。
3. 修改文件列表。
4. 已修复/待人工确认文件列表。
5. 验证步骤。
```
